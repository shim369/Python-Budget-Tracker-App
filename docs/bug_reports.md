## BUG-001 UTF-16 の CSV が「ヘッダー不正」になり、「文字コード非対応」と報告されない

| 項目 | 内容 |
|---|---|
| 発見日 | 2026-10-23 |
| 発見工程 / テスト | 工程3 / UT-SVC-13b(`ImportService` に UTF-16 のバイト列を渡すケース) |
| 対象 | `app/domain/csv_rules.py` の `decode()`(CSV-02) |
| 関連要件 | REQ-018、NFR-002 |

### 現象

UTF-16 で保存した CSV(Excel の「Unicode テキスト」など)を取り込むと、400 `CSV_HEADER_INVALID`(ヘッダー行が正しくない)が返る。
設計(CSV-02)では、UTF-16 は 400 `CSV_ENCODING_UNSUPPORTED`(文字コード非対応)となるはずだった。

### 再現手順

```python
from app.domain.csv_rules import decode
decode("date,amount,category\n".encode("utf-16"))     # → ("shift_jis", "d\x00a\x00…")
decode("date,amount,category\n".encode("utf-16-le"))  # → ("utf-8", "d\x00a\x00t\x00…")
```

### 期待結果

`None` を返す(API では 400 `CSV_ENCODING_UNSUPPORTED`)。

### 原因

- UTF-16 では、ASCII 文字が「文字コードの1バイト + `0x00`」の2バイトになる。この並びは UTF-8 としても有効なバイト列なので、BOM のない UTF-16LE / BE は UTF-8 として「デコードに成功」してしまう。
- BOM 付きの UTF-16(`FF FE`)は UTF-8 では失敗するが、cp932 では `FF` / `FE` がユーザー定義領域の文字として読めてしまい、Shift_JIS として成功する。
- 設計では「UTF-8 → cp932 の順に試してデコードできるか」で判定しており、UTF-16 がこの両方をすり抜ける場合を考慮していなかった。

**設計の考慮漏れ**として分類する。単体テストの仕様を作る段階で、異常系の同値クラス「UTF-16」に ASCII だけのヘッダーを使ったケースを加えたことで発見した。

### 修正内容

- `decode()` の先頭に、次の判定を追加した。
  - UTF-16 / 32 の BOM(`FF FE` / `FE FF`)で始まる → 対応外
  - NUL バイト(`0x00`)を含む → 対応外
- 正当な UTF-8 / Shift_JIS のテキストに NUL バイトは現れないため、正常なファイルには影響しない。
- 設計書 06_csv_import_design.md の CSV-02 の疑似コードに、同じ判定を追記した。

### 影響範囲

CSVインポート(API-24)の文字コード判定だけ。保存データへの影響はない(修正前もヘッダーエラーで中断しており、1行も取り込まれていなかった)。

### 再テスト結果

| テスト | 結果 |
|---|---|
| UT-CSV-05(UTF-16 BOM付き / LE / BE / CJK、UTF-32、NUL を含むバイト列の6ケースを追加) | 成功 |
| UT-SVC-13b(UTF-16 → CSV_ENCODING_UNSUPPORTED) | 成功 |
| UT-CSV-01〜04(UTF-8 / BOM付き / Shift_JIS / ASCII の回帰確認) | 成功 |
| 単体テスト全体(251件) | 成功 |

## BUG-002 日本語表示・狭い画面幅で、表の見出しやナビゲーションが1文字ずつ折り返される

| 項目 | 内容 |
|---|---|
| 発見日 | 2026-10-23 |
| 発見工程 / テスト | 工程4 / MT-01(全画面の表示確認。英語・日本語、幅 1280px と 390px) |
| 対象 | `static/index.html`、`static/css/custom.css` |
| 関連要件 | REQ-008、REQ-020、REQ-021 |

### 現象

1. 日本語表示のとき、表の見出し(「周期」「状態」「カテゴリ」)や日付(2026年10月22日)が1文字単位で折り返され、縦長の表になる。
2. 幅 390px のとき、ヘッダーのナビゲーションと言語ボタン(「日本語」)が1文字ずつ縦に並ぶ。
3. サブスク一覧で、操作ボタン4つが表の幅を超え、デスクトップ幅(1280px)でも「Delete」が切れて表示される。更新予定のバッジ(`<mark>`)も日付の途中で折り返される。
4. データ復旧バナーの「閉じる」ボタンが2行に折り返される。

### 再現手順

1. サンプルデータで起動し、日本語に切り替えて `#/subscriptions` と `#/expenses` を開く。
2. 画面の幅を 390px にする。

### 期待結果

見出し・日付・ボタンは1行に収まる。収まらない表は横スクロールで表示され(Pico の `.overflow-auto`)、ヘッダーは項目単位で折り返す。

### 原因

- Pico.css は表のセルや横並びのナビゲーションに折り返し禁止を設定していない。日本語は単語の区切りがないため、列幅が足りないと1文字ごとに改行される。
- サブスクの操作ボタンは `white-space: nowrap` の1行に4つ並べており、表の幅の計算で全体がはみ出していた。
- 画面設計(02)で、狭い幅でのレイアウトを項目定義に含めていなかった(**設計の考慮漏れ**)。

### 修正内容

- `th` と、日付・カテゴリ・周期・状態のセル(`td.nowrap`)、ナビゲーションのリンク、言語ボタン、バナーのボタンを折り返し禁止にした。
- ヘッダーの `nav` / `ul` に `flex-wrap: wrap` を指定し、項目単位で折り返すようにした。
- 操作ボタンを `.action-group`(flex-wrap)で囲み、ボタン単位で折り返すようにした。
- 更新予定のバッジを `<mark>` から `<small class="badge">` に変更し、状態の色(注意 / 超過)で表示するようにした。

### 再テスト結果

| テスト | 結果 |
|---|---|
| MT-01(英語・日本語 × 幅 1280px / 390px、5画面) | 合格。見出しと日付は1行、狭い幅の表は横スクロール、ヘッダーは項目単位で折り返す |
| 自動テスト一式(pytest 304件、node 32件) | 成功 |

## BUG-003 画面ファイルにキャッシュ制御がなく、更新後も古い CSS / JS が使われることがある

| 項目 | 内容 |
|---|---|
| 発見日 | 2026-10-23 |
| 発見工程 / テスト | 工程4 / BUG-002 修正後の MT-01 再テスト |
| 対象 | `app/main.py`(静的ファイルの配信) |
| 関連要件 | NFR-004(オフラインでの全画面の動作) |

### 現象

BUG-002 を修正してサーバーを再起動したあとも、ブラウザの一部の表示(iframe で読み込んだ画面)に修正前の `custom.css` が使われ、表示崩れが再現した。
新しい `index.html` と古い CSS / JS が組み合わされるため、JS モジュールの版が食い違うと画面が動かなくなるおそれもある。

### 再現手順

1. 画面を一度表示する。
2. `static/css/custom.css` を変更してサーバーを再起動する。
3. 同じブラウザで画面を開き直す → 変更前の CSS が適用されている(読み込まれたスタイルシートに、新しいルールが含まれていない)。

### 期待結果

更新後に画面を開き直すと、変更されたファイルが使われる。

### 原因

StaticFiles の応答には `ETag` / `Last-Modified` は付くが、`Cache-Control` が付かない。この場合、ブラウザは `Last-Modified` からキャッシュの有効期間を推測(ヒューリスティック)し、その期間はサーバーに確認せずにキャッシュを使う。

### 修正内容

`/` と `/static/*` の応答に `Cache-Control: no-cache` を付けるミドルウェアを追加した(`app/main.py`)。
`no-cache` は「使う前に必ずサーバーへ確認する」という指定で、変更がなければ `ETag` により 304 が返るため、通信量はほとんど増えない。API の応答は対象外とした。

### 再テスト結果

| テスト | 結果 |
|---|---|
| IT-OFF-03(新規追加):`/`・JS・CSS・辞書に `Cache-Control: no-cache`、`If-None-Match` で 304、API には付かない | 成功 |
| MT-01 の再テスト(古いキャッシュを一度取り直したあと、狭い幅の3画面) | 合格 |
| 自動テスト一式 | 成功 |
