## 4. 不具合

| ID | 件名 | 重要度 | 発見 | 原因の分類 | 状態 |
|---|---|---|---|---|---|
| BUG-001 | UTF-16 の CSV が「文字コード非対応」と報告されない | 中 | 工程3 UT | 設計の考慮漏れ(CSV-02) | クローズ |
| BUG-002 | 日本語表示・狭い画面幅での表示崩れ | 低 | 工程4 MT-01 | 設計の考慮漏れ(画面設計に狭い幅の定義がない) | クローズ |
| BUG-003 | 静的ファイルのキャッシュ制御がない | 中 | 工程4 MT-01 の再テスト | 設計の考慮漏れ(配信方式) | クローズ |

### 不具合の分析

- 3件とも、設計時の同値クラスや利用環境の想定に漏れがあったものだった(UTF-16、日本語の折り返し、ブラウザのキャッシュ)。
- 業務ルール(金額・日付・予算判定)からは不具合が出なかった。業務ルールを純粋関数に切り出し、設計書の境界値の表をそのままテストケースにした効果と考える。
- BUG-003 は、BUG-002 の再テストの中で見つかった。修正後の再テストを省略していれば見逃していた不具合である。

## 5. 既知の制約(不具合として扱わないもの)

| 項目 | 内容 | 対応 |
|---|---|---|
| ブラウザ標準の入力部品の言語 | 月・日付・ファイルの入力欄の表示は、ブラウザの言語設定に従う | 拡張案 X-08 |
| サブスク合計は現在の登録内容で計算する | 過去の月を表示しても、当時の価格ではなく今の登録内容で月額換算する(BR-04-1) | 拡張案 X-03 |

| 「金額」を空欄で送ったときのエラー文言 | 「必須」ではなく「値が正しくありません」と表示される。空欄は null として送られ、型エラー(INVALID_TYPE)と判定されるため(設計どおり) | 文言の改善は拡張案 X-09 |

## 6. 作業上の記録

工程2のコミットで、Git の操作ミスが1件あった。

- **事象**:`main.py` の削除が vendor のコミット(`f610dac`)に混ざった。feat と docs のコミットの順番が入れ替わった。

- **再発防止**:工程3以降は、コミットの前に `git diff --cached --name-only` で対象ファイルを確認するようにした。実際に工程3では、先にステージされていた `tests/.gitkeep` の削除を一度ステージ解除し、意図したコミットに入れた。
